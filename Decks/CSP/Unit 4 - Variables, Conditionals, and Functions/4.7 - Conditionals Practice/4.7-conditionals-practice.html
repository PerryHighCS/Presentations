The App Development Process

How Developers Build an App

Developers do not start by writing code. They start by learning what users need, then break that work into small pieces to build and test.

User Stories

What do users need?

Milestones

Which features meet those needs?

Tasks

What code builds each feature?

Tests

Does the code work as intended?

Why Gather User Stories?

You are not the only person who will use your app, so you cannot just guess what it should do. A user story records a real need in the user’s own words. It tells you which features are worth building and when a feature is done.

This is the big picture for the next three slides, which zoom in on each step. Ask students about an app feature they never use, or one they wish existed: that gap is what user stories are meant to catch.
The App Development Process

Start With User Stories

A user story describes what someone needs or wants from the app, written from the perspective of a person who might use it. One app has many users, and each one can have their own stories.

“I would like to be able to save my favorite items.”

One app has many users, and each user has their own needs. Reveal the speech bubble: this is one user story. Ask students for another user story they might write for an app they use every day.
The App Development Process

User Stories Become Milestones

Each user story becomes a milestone in developing the app. A milestone describes one feature to build so that the app meets that user’s need.

User Story

“I would like to be able to save my favorite items.”

Milestone

Create the ability to save favorite items within the app.

The user story is in the user's words; the milestone restates it as a feature the developer will build.
The App Development Process

Milestones Become Tasks

To accomplish a milestone, we complete tasks. Each level in today’s lesson focuses on a single milestone and the tasks needed to accomplish it.

Milestone

Create the ability to save favorite items within the app.

Tasks

1. Make a favorite button.

2. Save data into a variable when the user clicks the button.

Tasks are the concrete coding steps. In today's levels, most tasks ask students to write a conditional that sets a variable or changes what the screen shows.
Check In

A MindEase user says, “I want the app to tell me whether my mood today is high or low.” Is this a user story, a milestone, a task, or a test?

Answer: a user story. It is written in the user's own words and describes what they want, not how the app will do it.
Check In

The milestone is “Show the user whether their happiness level is High or Low.” Which choice is a task for that milestone?

Answer: "If the rating is higher than 5, assign happinessLevel a value of High." That is a concrete coding step, and it needs a conditional. "I want to know whether I am having a good day" is a user story, the second choice restates the milestone itself, and running the tests is how you check the tasks, not a task.
Working Through a Level

Three Steps in Every Level

Each level you complete also completes a milestone in your app. Approach every level the same way.

1. Read

Open the green user story accordion to understand what the user needs.

2. Build

Complete the tasks. Each level has one to three tasks that achieve the milestone.

3. Test

Run the tests for the level to make sure your code works as intended.

Stress step 3: a level is not done until its tests pass. If a test fails, go back to the user story and the task hints before asking for help.

Exit Ticket

Pick one milestone you completed today. What was the user story behind it, and what conditional did you write to accomplish it?

Strong answers name the user's need, then describe the condition they checked and what the code did in each case (for example, "if the rating is higher than 5, happinessLevel is High; otherwise it is Low").
