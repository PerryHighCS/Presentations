Conditionals Make

The Museum Ticket Generator

Today you will write the code for the Museum Ticket Generator. The screen is already designed for you.

A visitor picks the day they are visiting, picks their age, and can type a discount code. When they click the button, the app works out the price and prints a ticket.

Your code will use conditionals to decide which price each visitor pays.

This lesson has one main level plus the submission. Students can try the app and plan with a partner, but each student builds and submits their own app.
Step 1

Try the App

Open Lesson 8, Level 1 on Code.org and make tickets for different combinations of inputs.

  • Make a ticket for a weekend.
  • Make a ticket for a weekday (Monday to Friday) for someone 18 or younger.
  • Try the discount code FREEFRIDAY on a Friday.

Discuss With a Partner

  • What variables would you need to program this app?
  • Where does this app use conditionals?
Variables: the day, the age, the discount code, and the price. Conditionals: deciding the price from the day, the age, and the code. Some students will also notice the app has to check whether the code matches exactly.
Check In

Where does the Museum Ticket Generator use conditionals?

Describe one decision the app makes and what information it uses to make it.

Listen for the price decision and which inputs it depends on (day, age, and code). Group answers that name the same decision; students who only say "the button" are describing the event handler, not a conditional.
Step 2 · Plan

The Pricing Rules

Your app has to follow these rules. Plan a flowchart for them in your activity guide before you write any code. There is more than one correct way to draw it.

$10

On the weekend ("Saturday" and "Sunday"), everyone pays the full price.

$5

On weekdays (Monday through Friday), visitors who are 18 or younger pay $5.

$0

The discount code "FREEFRIDAY" gets anyone in free on a Friday. No other code works, and this code only works on Fridays.

The rules never say it outright, but everyone else pays the full $10: adults on weekdays without the code, and anyone with a wrong code. Ask students where that case lives in their flowchart. The FREEFRIDAY check has to come before the age check on Fridays, which is the "most specific case first" idea from 4.6.

Check In

A 15-year-old buys a ticket for Saturday and types the discount code FREEFRIDAY. What price should the app show?

Answer: $10. Saturday is the weekend, so everyone pays full price; the code only works on Fridays, and the $5 youth price only applies on weekdays. Students who answer $0 are ignoring the Friday part of the code rule; students who answer $5 are ignoring the weekday part of the age rule.

Before You Submit

Check Your Work

Check your app against the rubric before you click Submit on Code.org.

Input

An onEvent is created for every required input.

Variables

Variables store every piece of information the app uses.

Conditional Logic

The price is correct for every combination of age, day, and code.

Output

The ticket shows the day, age, and price.

Runs Without Errors

No errors are present in the code.

Coding Comments

Comments explain every onEvent and the conditional logic.

This is the Extensive Evidence column of the rubric. The conditional logic row is where most points are lost: have students run all eight test cases before submitting.

Step 5

Sentence Starters

These sentence starters may help you write your response. You can use or change some or all of them.

  • One of the Boolean expressions in my program is.
  • This expression uses the relational operator == to check if.
  • If this expression is true, then.
  • Otherwise, the program.
  • This influences the program’s behavior by ensuring that.
  • Without this expression, the program would not be able to.
A strong response quotes a specific expression from their code (such as day == "Friday"), says what happens when it is true and when it is false, and connects it to the price the visitor sees.
