Variables Investigate

Last lesson we traced variables by hand. Today we will investigate working apps on Code.org to see how real programs use variables to store, update, and display information.

Computer Science Principles, Unit 4 Lesson 2. This lesson follows the TraceLift tracing work in 4.1, so students already have a mental model of var, assignment, and reassignment.
Warm Up

What does a variable do?

Answer in your own words. Think about what you did with the Memory Trace in the last lesson.

Collect responses, then share a few. Listen for ideas like "it stores a value," "it gives a name to a value," and "the value can change." Do not formalize the definition yet; the vocabulary slide at the end does that.

Debugging Tool

Adding a Watcher

A watcher shows the current value of a variable while your app runs.

In the Watch panel at the bottom right, type a variable name like tempF and click +.

Run the app and click the buttons. Watch the value change each time the variable gets a new value.

Point out that tempF shows "undefined" before the app runs, just like a declared but unassigned variable in our Memory Trace. The watcher is App Lab's version of the Memory Trace column.
2

Modify the Thermostat

Step 1Modify the code so the temperature changes by 2 degrees when the up and down arrows are clicked.

Step 2Check your work: add a watcher for the temperature variable and run the app. Each click should change the watched value by exactly 2.

Common mistake: students change only one button. Have them test both directions with the watcher visible.
3

How Does Math.round Work?

Look through the code. A new variable, tempC, now stores the temperature in Celsius.

Give your best answer: how do you think Math.round works? Check lines 3, 15, and 28.

Math.round takes a number and gives back the nearest whole number. When tempF is 70, the expression evaluates to 21.11…, so tempC gets 21.

Collect guesses through the activity first, then reveal the explanation. Connect to "evaluate first, then assign": the whole right side, including Math.round, is evaluated to one value before tempC gets it. Ask why the same calculation appears three times (start value, down button, up button).
4

Celsius and Display Strings

Step 1Move to dot 4 on Code.org. Run the app and discuss what changed from the last version.

Step 2Try deleting just the Math.round in lines 3, 15, and 28. What happens? Then add it back in.

Step 3Modify the code so that no space displays between the temperature and the unit, so the screen shows 70F and 21C.

Without Math.round, the Celsius display shows long decimals like 21.11111111111111 C, which shows students why the rounding is there. The space comes from the string " F" (space then F) being joined to the number. Students need to change the strings in the var lines and in both event handlers. If they only change line 4, the space comes back after the first click.

Reading Text with getText

Step 1Move to dot 6 on Code.org.

Step 2Read the code and discuss with your partner what has changed and what has stayed the same.

Step 3Discuss as a class: how does getText() work?

getText("nameInput") looks up the screen element with that id and gives back the text it holds right now, as a string. We can store that string in a variable like userName.

Step 4Modify the code: use string concatenation to add an exclamation point "!" to the end of the string stored in userName. Concatenation joins two strings into one with the + operator. When you are done, the screen should display:

Hold the getText reveal until after the class discussion. For the modify, students should use string concatenation, such as userName = userName + "!"; or adding "!" when the string is built. Either is fine as long as the exclamation point ends up at the end.
Patterns

Code Patterns

Programmers run into the same kinds of problems over and over, such as counting clicks or building a message out of smaller pieces. A code pattern is a common, reusable way of solving one of those problems.

You have already used patterns today without naming them. The thermostat buttons updated a variable with each click, and the display joined a number and a string to build what appeared on the screen.

Once you can recognize a pattern, you can reuse it in your own apps instead of solving the same problem from scratch. For each pattern, we will record its name, its block code, and its text code.

Frame patterns as a toolbox students will keep building through the unit. Ask: "Where in the thermostat app did we see the same kind of code more than once?" (The up and down buttons both update a variable and redisplay it.) The next two slides name the two patterns from today.
Pattern

Counter Pattern with Event

Block mode

text mode
var myVar = 0;

onEvent("id", "click", function() {
    myVar = myVar + 1;
});

The variable is created once, outside the event, so it keeps its value between clicks. Each click, myVar gets its current value plus 1. The thermostat buttons used this same pattern.

Ask: what would happen if var myVar = 0 were moved inside the onEvent? (It would reset to 0 every click, so the counter would never go past 1.) Students should add this pattern to their pattern list or notes.
Pattern

Variable with String Concatenation

Block mode

text mode
var myString = "rock";
var myOtherString = "roll";

var myStory = myString +
    " and " + myOtherString;

The + operator joins strings together. Look up each variable’s current value, then join them in order:

myStory←"rock and roll"
Point out that the spaces come from the " and " string, not from the + operator. This connects directly to the Level 4 modify, where removing a space meant changing a string.
Review

What can be stored in a variable?

Why is using a meaningful name for the variable important?

Expected ideas: numbers, strings, text a user typed (via getText), results of expressions like Math.round(...). Meaningful names like tempF and userName make the code readable for partners and your future self; myVar tells you nothing about what it stores. The third question checks the Level 4 lesson that + does not add spaces.
Vocabulary
Variable

A reference to a value (or a value that results from evaluating an expression) that can be used repeatedly throughout a program.

This is the formal AP CSP definition. Have students copy it into their vocabulary list and compare it with their warm-up answer.
