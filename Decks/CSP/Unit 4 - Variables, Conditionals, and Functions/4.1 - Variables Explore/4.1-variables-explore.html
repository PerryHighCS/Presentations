Unit 4 · Lesson 4.1

Variables Explore

We have used parameters to give names to values passed into functions. That makes our functions more useful, because they can behave differently depending on the values they receive.

Today we are going to become the computer to see how giving names to values actually works.

Do not begin with a formal definition of variable. Start from something students already know operationally: functions with parameters (Unit 3 lessons 11 and 12).

Round 1 · Parameters Name Values

Parameter and Argument

definition
function cheer(name) {

name is the parameter. It is the name the function uses for a value.

call
cheer("Pumas");

"Pumas" is the argument. It is the value the call supplies.

name
"Pumas"

The function call supplies the starting value for the parameter. Read it as: name gets the value "Pumas" when the function is called.

Keep this practical. The goal is not a vocabulary lecture. Common misconception: "the parameter is the argument." Response: the argument supplies the value; the parameter is the name used inside the function.

Beyond Parameters

Naming a Value Ourselves

Parameters are useful because a function can receive a value and give it a name. But what if the value does not come from a function call? What if we want to keep track of a value while our program is running?

Imagine the computer had a piece of scratch paper where it could write a name next to a value, and then use that name later.

JavaScript gives us a way to create those named places. Each one is called a variable.

javascript
var score;
scratch paper
score10
lives3
level2
Ask before revealing anything: "If parameters are names for values passed into a function, how could we use that same idea when we want the program itself to keep track of something?" Let students suggest examples like score, lives, clicks, temperature, name, or level. Then: "We can think of a variable as a named spot on the computer's scratch paper."
Round 4 · var Creates Memory

Declaring a Variable

Read var score; as “create a variable named score.” A variable is a named place the program can use to represent a value.

Now give the formal variable idea. Contrast gently with parameters. Parameter: the function definition creates the named value, and the function call supplies its starting value. var: creates the named place, but it still needs a value assigned. Point out that there is no function box here; this column belongs to the program itself.
Round 5 · Assignment

Assignment

Read score = 3; as “score gets 3.” The variable on the left gets the value from the right. On the AP exam, this same statement is written score ← 3.

Misconception: "= means both sides are equal." Response: read = as "gets." Evaluate the right side first, then store that result in the variable on the left. The AP reference sheet arrow points the direction the value moves.
Round 5 · Reassignment

Reassignment

What happens to the value 3 when score gets a new value?

Misconception: "the crossed-out values are still stored." Response: the crossed-out values are our human trace history. Only the newest uncrossed value represents the program's current state.

Data Types

Values Have Types

Numbers

3   10   42

So far, most of our values have been numbers.

Strings

"Pumas"   "hello"   "407"

A string is a sequence of characters inside quotation marks. The quotes tell the computer to treat those characters as text.

The kind of value is called its data type. Numbers and strings are two data types we will use in JavaScript, and we have been using both since our very first trace.

123 is a number, but "123" is a string made of three characters.

score is the name of a variable, but "score" is just the word score in a string.

A Variable Without a Value

What Is in an Empty Column?

When we declare a variable, its Memory Trace column starts out blank. What do you think happens if the program uses it right away?

Extension. Take a few predictions before stepping. Students often guess 0, an error, or nothing. The flap shows undefined, but the Memory Trace column stays blank on the whiteboard; blank means "nothing assigned yet."
Declare and Initialize

Initialization

two statements
var score;
score = 0;

Between these two statements, score has the value undefined.

one statement
var score = 0;

If we already know the starting value, we can declare the variable and initialize it at the same time.

To declare a variable means to create it with var. Initialization is the first assignment of a value to a variable. Today’s TraceLift sheets keep the two steps separate so you can see each one happen.

Also mention: if you call a function that takes a parameter and do not pass a value, that parameter also gets undefined. This slide and the previous one are extensions; skip them if time is short.
Wrap-Up

Programs Use Names to Represent Values

We have now seen two ways those names are created.

Parameters

function cheer(name) { ... }
cheer("Pumas");

The function definition creates the name, and the argument in the call supplies its starting value.

Variables

var score;
score = 10;

var creates the name, and assignment supplies or changes its value.

Wrap-Up

Tracing Rules

When you see var

Create a new column in the Memory Trace.

When you see an assignment

Evaluate the right side, then store the result in the variable on the left.

When a name is inside an expression

Look up its current value, substitute it, and evaluate.

When you call a function

Evaluate the arguments, give the call its own memory box, and use those values to initialize the parameters.

Remember: copying a value does not create a permanent connection.
