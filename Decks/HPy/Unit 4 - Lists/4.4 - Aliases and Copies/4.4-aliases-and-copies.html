Aliases and Copies

Aliases versus copies

Aliases are two variables that refer to the same list. A change made through either name shows up through both, because there is only one list.
Copies are two lists that are equal but separate. A change to one copy never changes the other.

Python checks for aliases with is. L is M is True only when both arrows point at the same object, and L is not M is its opposite. Compare that with ==, which only asks whether the values match.

  • If L is M, then L == M must be True, since a list always equals itself.
  • If L == M is False, then they cannot be aliases.
  • Copies have L == M but L is not M.

Making a Copy

copy.copy(L)

To get a separate list with the same values, import copy and call copy.copy(L). It creates a new list, so the result is a copy, not an alias.

Python has other ways to copy a list, and you will see them in other people's code. Recognize them, but in your own code always use copy.copy, because it says exactly what it does.

do it this way
import copy
L = [1, 3]
N = copy.copy(L)
print(L == N, L is N)   # True False
recognize, but don't use
c = a[:]       # any slice is a new list
d = a + []     # + makes a new list
e = list(a)
f = a.copy()
g = a * 1      # * makes a new list
Breaking Aliases

Reassigning moves an arrow

The Key Distinction

Mutation versus reassignment

Mutation changes the object at the end of the arrow: M[0] = 42, M.append(4), M.sort(). Every alias sees the change.
Reassignment of the variable itself, like M = [42, 3] or M = copy.copy(M), points M at a different object. The old list and its other aliases are untouched, and the alias is broken.

This holds even when the new list is equal to the old one. After M = [42, 3], L == M can still be True, but L is M is False.

4.2.6 List Operators

L = L * 2 is not the same as L *= 2

Make an alias M first, then change L. If M sees the change, the operation was mutating. This alias test works for any operation you are unsure about.

non-mutating: a new list
L = ["a", "b"]
M = L
L = L * 2
print(L is M)   # False
print(M)        # ['a', 'b']
mutating: the same list
L = ["a", "b"]
M = L
L *= 2
print(L is M)   # True
print(M)        # ['a', 'b', 'a', 'b']

+ and += follow the same rule. L = L + [3] builds a new list, and L += [3] mutates L, just like L.extend([3]).

Mutating vs Non-Mutating

Four patterns that help you remember

Assignment operators mutate; plain operators don't. += and *= change the list. + and * build a new one.
Methods mutate; past-tense functions don't. L.sort() and L.reverse() change L. sorted(L) and reversed(L) leave it alone.
Non-mutating operations return a new list. Store the result, as in M = sorted(L) or M = L + [3], or the new list is lost.
Mutating methods return None. They change the list you already have, so there is nothing new to hand back. That makes L = L.sort() a trap: sort sorts the list, then the assignment points L at None, and the sorted list is lost. pop is the exception; it returns the value it removed.

When the patterns are not enough, run the alias test: make M = L, do the operation on L, and print M.
