4.6 Removing Items in a Loop

the case of the disappearing reds · why removal skips items · three safe ways to remove them all

The Task

Remove every value that matches

Python has L.remove(v), but it only removes the first match. Cleaning up text means stripping out every filler word, and the tray needs every red item gone. So we need our own removeAll.

The obvious plan is to loop over the indexes and pop each match as we find it. Today we find out why the obvious plan fails, in two different ways, and how to fix it.

Trace It · Bug 1

The range was decided at the start

Explain It

A for loop counts once

range(len(L)) is evaluated one time, when the loop starts. The list had 4 values then, so i will be 0, 1, 2, and 3 no matter what happens to the list. Once a value is popped, index 3 no longer exists.

A while loop checks its condition before every pass, so while i < len(L) always uses the list's current length. That fixes the crash.

Rule: never add or remove values in a list while a for loop is walking over that same list.

Trace It · Bug 2

One red survives

Explain It

The next item slides under your finger

When pop(i) removes a value, the value that was at i + 1 shifts left into index i. That value has not been checked yet, but then i += 1 moves past it.

So the bug only shows up when two matches are next to each other. A test with [1, 2, 3] passes. A test with [2, 2] fails. Good tests include adjacent matches on purpose.

The fix: after a pop, stay where you are. Only move i forward when nothing was removed.

Checkpoint · Index Shifting

What happens?

  • AIt crashes and never prints anything
  • BIt correctly prints [1, 3, 3, 4]
  • CIt incorrectly prints [1, 3, 2, 3, 4]
  • DIt incorrectly prints [1, 3, 3]
main.py
def removeAll(L, v):
    i = 0
    while i < len(L):
        if L[i] == v:
            L.pop(i)
        i += 1

L = [1, 3, 2, 2, 3, 2, 4]
removeAll(L, 2)
print(L)
The 2s at indexes 2 and 3 are adjacent. Popping index 2 shifts the second 2 into index 2, and i moves on to 3, so that 2 survives. The last 2 is not adjacent to another match, so it is removed.
The Fix

Advance only when nothing was removed

4.2.10 removeAll(L, v)

Why the fixed version works

1. It uses while, so len(L) is checked before every pass with the list's current length.
2. It does not add 1 to i after a pop, so the value that shifted into index i gets checked.

This version is mutating: it changes the caller's list and returns None. That is its job.

main.py
def removeAll(L, v):
    i = 0
    while i < len(L):
        if L[i] == v:
            L.pop(i)
        else:
            i += 1

L = [1, 3, 2, 2, 3, 2, 4]
removeAll(L, 2)
print(L)   # [1, 3, 3, 4]
Safer Alternatives

Two other ways to remove them all

simple, but slow
def removeAll(L, v):
    while v in L:
        L.remove(v)

Short and correct, but each pass searches the list twice: once for in and again for remove. On a long list that is a lot of wasted work.

build a new list instead
def filterOut(L, v):
    result = []
    for value in L:
        if value != v:
            result.append(value)
    return result

The 4.5 filter pattern. It never changes the list it loops over, so nothing can shift. It returns a new list and leaves L alone.
