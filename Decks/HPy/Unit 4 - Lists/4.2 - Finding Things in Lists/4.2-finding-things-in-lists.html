4.2 Finding Things in Lists

membership · counting and searching · summarizing · comparing lists

The Question

What can a program learn without changing the list?

A detective reads the evidence but does not rewrite it. Today's tools all read a list and report something about it, and none of them change the list.

main.py
review = "great fan but great noise"
words = review.split(" ")
  • Does the word "broken" appear at all?
  • How many times does "great" appear?
  • Where is the first "but"?
  • Which word comes first alphabetically?
4.2.6 List Operators

in and not in

v in L is True when v equals one of the values in L. v not in L is its opposite.

With strings, in finds substrings: "ab" in "abc" is True. With lists it does not find sublists. It only compares v to each single value.

main.py
L = [1, 2, 3]
print(2 in L)          # True
print(4 not in L)      # True
print([1, 2] in L)     # False

words = ["fan", "noise"]
print("noise" in words)   # True
print("no" in words)      # False
print("no" in "noise")    # True
Checkpoint · Membership

Which one prints True?

  • Aprint([2, 1] in [1, 2, 1])
  • Bprint("ab" in ["a", "ab", "abc"])
  • Cprint("ab" in ["a", "b", "c"])
  • Dprint("ab" in ["A", "AB", "ABC"])
Only "ab" in ["a", "ab", "abc"] is True, because "ab" equals one of the values. In C, "a" and "b" are there but never as one value. In D, comparisons are case sensitive. In A, the list has no value that is itself the list [2, 1].
4.2.8 List Methods

count and index

These work just like the string methods. L.count(v) returns how many times v appears. L.index(v) returns the index of the first v.

L.index(v) crashes with a ValueError when v is not in the list. L.count(v) simply returns 0.
main.py
L = [5, 3, 8, 7, 8]
print(L.count(8))    # 2
print(L.count(9))    # 0
print(L.index(8))    # 2
print(L.index(9))    # crash!
No find() for Lists

Two ways to search safely

Strings have s.find(v), which returns -1 instead of crashing. Lists do not have a find method.

You can check v in L before calling L.index(v), or you can write your own search. The loop on the right is the pattern behind most of today's tools: visit every index, and return as soon as you find a match.

main.py
def listFind(L, v):
    for i in range(len(L)):
        if L[i] == v:
            return i
    return -1

print(listFind([5, 3, 8], 8))  # 2
print(listFind([5, 3, 8], 9))  # -1

if 9 in L:
    print(L.index(9))
Checkpoint · Searching

Which is not a good way to search a list?

  • AUse L.index(v), but first check that v in L is True
  • BWrite your own function listFind(L, v)
  • CConvert L to a string with s = str(L), then use s.find(v)
str(L) produces text such as "[5, 3, 8]". s.find returns a character position in that text, not a list index, and it can match pieces of values.
Explain It

Why str(L) does not work

str(L) turns the list into text: brackets, commas, spaces, and digits. s.find searches that text one character at a time, so it answers a different question.

It returns a character position, not a list index: the 3 is character 4 of the text, but index 1 of the list. And it matches pieces of values: it finds an 8 inside 18, even though 8 is not in the list.

The two safe ways both work with the list's values: check v in L before calling L.index(v), or loop over the indexes yourself, like listFind.

main.py
L = [5, 3, 18]
s = str(L)
print(s)             # [5, 3, 18]

print(s.find("3"))   # 4
print(L.index(3))    # 1

print(s.find("8"))   # 8
print(8 in L)        # False

Why was the last line False?

4.2.7 Builtin Functions

Summarizing a list

len(L), min(L), max(L), and sum(L) do what their names say.

The values must be compatible. min and max need values that can be compared, so strings compare alphabetically, but a mix of numbers and strings crashes. sum needs numbers only, even though + works on strings.

main.py
stars = [4, 5, 2, 5, 3]
print(len(stars))   # 5
print(min(stars))   # 2
print(max(stars))   # 5
print(sum(stars) / len(stars))  # 3.8

print(max(["cats", "dogs", "birds"]))
# dogs
print(max([42, "dogs"]))   # crash!
print(sum(["a", "b"]))     # crash!
Checkpoint · Summaries

Which statement must be False?

You know that min(L) == 0, sum(L) == 1, and len(L) == 2.

  • AL contains no negative values
  • Bmax(L) == 1
  • CL contains exactly one 1
  • DL contains no odd values
Two values, the smaller is 0, and they add to 1, so L holds 0 and 1 in some order. It contains the odd value 1.
Comparison Operators

When are two lists equal?

L == M is True when the lists have the same length and every value equals the value at the same index in the other list. Otherwise L != M is True.

Order matters, and so does length. Two lists with the same words in a different order are not equal.

main.py
print([1, 2, 3] == [1, 2, 3])     # True
print([1, 2, 3] == [3, 2, 1])     # False
print([1, 2, 3] == [1, 2, 3, 4])  # False
print([1, 2] != [1, 2])           # False
< <= >= >

Lists compare like dictionary words

Python compares lists the way a dictionary orders words. It finds the first index where they differ and compares those two values, so dog comes before duck.

If one list runs out first and everything matched, the shorter list is a prefix and comes first, so dog comes before dogs.

main.py
print(["d","o","g"] < ["d","u","c","k"])
# True: "o" < "u" at index 1
print(["d","o","g"] < ["d","o","g","s"])
# True: a prefix comes first
print([1, 3, 4] <= [1, 2, 3, 4])
# False: 3 > 2 at index 1
print([1, 2, 3] >= [1, 2, 3, 4])
# False: the prefix is smaller
Checkpoint · Ordering

Which list is less than all the others?

  • A["e"]
  • B["dog"]
  • C["d", "o"]
  • D["d", "o", "g"]
["d", "o"] is a prefix of ["d", "o", "g"], so it is smaller. Against ["dog"], the first values differ: the string "d" is a prefix of "dog", so "d" < "dog". Everything starting with "d" is less than ["e"].
type() and list()

Checking and converting

type(L) == list is True for any list. Notice that list is a type, not the string "list".

Given a sequence, list(s) converts it into a list. A string becomes a list of its characters, which is handy for working with letters one at a time.

main.py
L = [1, 2]
print(type(L) == list)     # True
print(type(L) == "list")   # False

print(list("wow"))   # ['w', 'o', 'w']
print(list(range(3)))   # [0, 1, 2]

VS Code · word_detective.py

Word Detective

In VS Code, create word_detective.py in your Unit 4 folder. Each function takes a sentence, a string like "the red fox saw the blue sky". Start each one by splitting the sentence into a list of words, then use a loop, not the builtin shortcut, so you practice the algorithm. Test each function with assert before moving on.

  1. countWord(sentence, target) returns how many times the word target appears. Check it against sentence.split(" ").count(target).
  2. findFirst(sentence, target) returns the index of the first word equal to target, counting words from 0, or -1 if it is missing.
  3. countMatches(sentence, targets) takes a list of words as targets and returns how many words in the sentence appear in it. For example, countMatches("the red fox saw the blue sky", ["red", "blue", "green"]) returns 2.
In countMatches, use `in` against targets inside the loop; that is a fine use of a builtin. Ask for a test with an empty sentence: "".split(" ") returns [""], a list holding one empty string, not an empty list, which surprises most students. Also ask for a test where every word matches.
