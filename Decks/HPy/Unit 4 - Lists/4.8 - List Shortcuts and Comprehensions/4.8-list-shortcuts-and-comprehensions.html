4.8 List Shortcuts and Comprehensions

sorted and reversed · split, splitlines, and join · list comprehensions · refactoring safely

The Question

When does a shortcut make code better?

You can now write any list algorithm with a loop. Python also has shortcuts that do common jobs in one line. A shortcut is worth using when it is clearer than the loop and does exactly the same thing, including whether it changes the list.

That second part is where shortcuts bite. Many shortcuts come in pairs that look alike, where one builds a new list and the other mutates the old one. Today's job is to learn each pair and then refactor code without changing what it does.

4.2.7 sorted()

sorted(L) versus L.sort()

sorted(L) is a function that returns a new sorted list and leaves L alone. L.sort() is a method that mutates L and returns None.

Both accept reverse=True to sort from largest to smallest. This is the clean fix for last lesson's median.

main.py
L = [8, 3, 2, 6, 4]
M = sorted(L)
print(L)   # [8, 3, 2, 6, 4]
print(M)   # [2, 3, 4, 6, 8]

N = sorted(L, reverse=True)
print(N)   # [8, 6, 4, 3, 2]

def median(L):
    M = sorted(L)
    return M[len(M) // 2]
Trace It

One builds, one mutates

4.2.7 reversed()

reversed(L) is not a list

You might expect reversed(L) to return a reversed list. Instead it returns a special iterator object that hands out L's values from back to front.

A for loop can use it directly. To get an actual list, wrap it: list(reversed(L)). It never mutates L. Compare L.reverse(), which does.

main.py
L = [8, 3, 2]
print(reversed(L))
# <list_reverseiterator object ...>

print(list(reversed(L)))   # [2, 3, 8]
print(L)                   # [8, 3, 2]

for v in reversed(L):
    print(v)               # 2, 3, 8

L.reverse()
print(L)                   # [2, 3, 8]

4.2.9 List-Related String Methods

Text to lists and back

s.split(c) breaks a string at each c. s.splitlines() breaks it at each line ending, which is how you turn a file of reviews, one per line, into a list of reviews.

c.join(L) goes back, putting c between each pair. Use "\n" to make lines, or "" to glue strings together with nothing between.

main.py
text = """Great fan!
Too loud.
Works fine."""
reviews = text.splitlines()
print(reviews)
# ['Great fan!', 'Too loud.', 'Works fine.']

print(" | ".join(reviews))
# Great fan! | Too loud. | Works fine.
print("".join(["H", "i", "!"]))   # Hi!
Checkpoint · split and join

Which statement is false?

  • AFor a multiline string s that does not end in a newline, if L = s.splitlines(), then s == "\n".join(L) must be True.
  • BIf L is a list of names, then ",".join(L) is a comma-separated string of those names.
  • CFor any non-empty string s that does not end in a newline, s.split("\n") == s.splitlines() is always True.
  • DFor any list L, if s = "-".join(L), then "-" in s must be True.
If L has zero or one values, join has no pairs to separate, so no "-" appears: "-".join(["a"]) is "a".
4.2.11 List Comprehensions

A loop that builds a list, in one line

[expression for variable in iterable] builds a new list. Read it from right to left: the iterable is what you loop over, the variable takes each value in turn, and the expression computes what goes into the result.

The iterable can be a list, a range, or a string.

the loop
L = [2, 4, 1, 5]
M = []
for v in L:
    M.append(v ** 2)
print(M)   # [4, 16, 1, 25]
the comprehension
M = [v ** 2 for v in L]
print(M)   # [4, 16, 1, 25]
print([v ** 2 for v in range(5)])
# [0, 1, 4, 9, 16]
Using a Conditional

Add if to filter

Adding if condition at the end, as in [expr for v in L if cond], keeps only the values where the condition is True. That is the filter and transform pattern from 4.5, in one line.

Keep comprehensions short and clear. If you need more than a simple expression and a simple condition, write the loop instead.

main.py
L = [2, 4, 1, 5]
print([v ** 2 for v in L if v % 2 == 0])
# [4, 16]

words = ["Great", "fan", "but", "LOUD"]
print([w.lower() for w in words
       if len(w) > 3])
# ['great', 'loud']

Code Makeover

Shorter, and still the same program

Run the tests first to see them pass. Then rewrite each function body to be shorter and clearer, using sorted, join, or a comprehension. Run the tests after every change. These are regression tests: they prove the makeover did not change behavior, including leaving words alone.

Targets: [w.lower() for w in words if len(w) <= 3]; return sorted(words); return " ".join(words). Uppercase letters sort before lowercase, which is why "LOUD" and "The" come first. If a student writes words.sort() in alphabetical, the last assert catches it.
Readability

When to keep the loop

The work is more than one expression and one condition. Nested ifs, several steps, or a counter all belong in a loop.
The goal is to mutate a list. A comprehension always builds a new list. It cannot be a mutating removeAll.
You need the index or a neighbor. Loops like repeatedWords from 4.5 read more clearly as loops.
Nobody on your team can read it yet. Clear code is code your teammates can trace. That matters whenever you share code.
