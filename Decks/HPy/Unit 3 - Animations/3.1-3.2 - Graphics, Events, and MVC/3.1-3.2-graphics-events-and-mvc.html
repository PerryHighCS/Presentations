3.1–3.2 Graphics, Events, and MVC

drawing shapes and labels on a canvas · responding to mouse presses · organizing an app with Model-View-Controller

3.1 Getting Started

An animation is graphics plus events

Graphics are drawings made from basic shapes: rectangles, circles, lines, and text labels. Events bring those drawings to life by letting them respond to the mouse, the keyboard, and the passage of time. Put the two together and you get an animation that feels like a real web or phone app.

We build these apps the way real apps are built. Our approach is called Model-View-Controller, or MVC. It takes a little more setup than the shortcuts you may have seen in earlier courses, but it scales up cleanly to large projects. In a later unit, that same structure will carry us all the way to Tetris.

3.2.1 Drawing Rectangles and Labels

the shape of every graphics program, the canvas coordinate system, and the tools that help you read a drawing

Our First Drawing

A blue rectangle in the corner

This program draws a 100×200 blue rectangle in the top-left corner of the canvas, the window where all our drawing happens.

You'll follow this pattern in every graphics program we write this unit.

main.py
from cmu_graphics import *

def redrawAll(app):
    drawRect(0, 0, 100, 200, fill='blue')

def main():
    runApp()

main()
The Skeleton, Line by Line

Four parts of the pattern

from cmu_graphics import *   brings in all of the drawing functions. Imports go at the top of your code, so this will be the first line of every graphics program.
def redrawAll(app):   is where all drawing happens. Only this function, and any helpers it calls, may draw. We will see why in the MVC notes.
runApp()   opens the app window and starts it running. Call it from main, following our usual best practice.
main()   is still your one and only line of top-level code.
You never call redrawAll yourself. The cmu_graphics library calls it for you, over and over, to keep the screen up to date.
The drawRect Function

drawRect(left, top, width, height)

drawRect's four required arguments are, in order, the left edge, the top edge, the width, and the height.

Add fill='blue' to set the color. Any name from the CMU color list works.

drawRect(0, 0, 100, 200, fill='blue') means: left at x=0, top at y=0, 100 wide, 200 tall.

When you hover over a running drawing, the Inspector shows you the exact coordinates and sizes of every shape. It is how you figure out the numbers you need to reproduce a drawing yourself. Watch carefully.

The Canvas

Up is down

The canvas is a grid of pixels, 400 by 400 by default. Its real size lives in app.width and app.height.

  • x is 0 on the left and grows to the right.
  • y is 0 at the top and grows downward, the opposite of math class.
  • (0, 0) is the top-left corner; (app.width, app.height) is the bottom-right.
  • The center is (app.width/2, app.height/2).
Putting It Together

Center a 200×300 red rectangle

drawRect positions a rectangle by its top-left corner, not its center. So to center it, start at the middle of the canvas and back up by half the rectangle.

The rectangle is 200 wide, so its left edge sits at app.width/2 - 100. It is 300 tall, so its top sits at app.height/2 - 150.

main.py
from cmu_graphics import *

def redrawAll(app):
    drawRect(app.width/2 - 100,
             app.height/2 - 150,
             200, 300, fill='red')

def main():
    runApp()

main()
Better Style

Name the numbers you did math on

The 100 and 150 in the last version are magic numbers: they came from arithmetic that is not visible in the code.

Store the width and height in well-named variables and let the code show the arithmetic. Now rectWidth/2 explains itself.

main.py
def redrawAll(app):
    rectWidth = 200
    rectHeight = 300
    drawRect(app.width/2 - rectWidth/2,
             app.height/2 - rectHeight/2,
             rectWidth, rectHeight, fill='red')
Checkpoint · Centering

Which call centers the rectangle?

The canvas is 400 by 400. You want a rectangle that is 100 wide and 40 tall, centered. Remember that drawRect takes the top-left corner.

  • AdrawRect(200, 200, 100, 40)
  • BdrawRect(150, 180, 100, 40)
  • CdrawRect(100, 40, 200, 200)
  • DdrawRect(50, 20, 100, 40)
Drawing Text

drawLabel(value, centerX, centerY)

drawLabel writes text on the canvas. The first argument is the string to draw. The next two are the (x, y) location of the center of the text, not a corner.

This call centers the words Some text on a 400 by 400 canvas.

main.py
from cmu_graphics import *

def redrawAll(app):
    drawLabel('Some text', 200, 200)

def main():
    runApp()

main()

3.2.2 Mouse Press Events

running code once at startup, storing state on the app object, and reacting to every click

Runs Once

onAppStart(app)

When an app starts, onAppStart(app) is called exactly once, before anything else happens.

Because onAppStart runs exactly once, its message appears in the console a single time when the app opens, and never again while the app keeps running.

main.py
from cmu_graphics import *

def onAppStart(app):
    print('Hello from onAppStart!')

def redrawAll(app):
    drawRect(0, 0, 50, 50, fill='cyan')

def main():
    runApp()

main()
The app Object

You can store your own values on app

There is only one app object shared by every cmu_graphics function. So a value you set in onAppStart is still there in redrawAll.

Here onAppStart sets app.rectLeft and app.rectTop, and redrawAll reads them back to place the rectangle.

main.py
from cmu_graphics import *

def onAppStart(app):
    app.rectLeft = 100
    app.rectTop = 200

def redrawAll(app):
    drawRect(app.rectLeft, app.rectTop,
             50, 50, fill='cyan')

def main():
    runApp()

main()
Reacting to Clicks

onMousePress(app, mouseX, mouseY)

onMousePress is called automatically every time the user presses the mouse. Along with app, it receives mouseX and mouseY: the exact spot that was clicked.

This program has no redrawAll, so nothing is ever drawn. It only prints. Press Run, then click inside the app window and watch the console.

main.py
from cmu_graphics import *

def onMousePress(app, mouseX, mouseY):
    print(f'You pressed the mouse at {mouseX},{mouseY}')

def main():
    runApp()

main()

Our First Animation

The rectangle follows your clicks

Change onMousePress so it updates app.rectLeft and app.rectTop to the click location. That is the whole animation.

Click, and the rectangle jumps there. redrawAll did not change at all; it just keeps drawing the rectangle wherever the stored values say.

from cmu_graphics import *

def onAppStart(app):
    app.rectLeft = 100
    app.rectTop = 200

def onMousePress(app, mouseX, mouseY):
    app.rectLeft = mouseX
    app.rectTop = mouseY

def redrawAll(app):
    drawRect(app.rectLeft, app.rectTop,
             50, 50, fill='cyan')

def main():
    runApp()

Three Things to Remember

How the pieces fit together

redrawAll clears everything first. Every call wipes the canvas and redraws it from scratch. You never erase old shapes yourself; you just describe the whole picture again.
You never call the event handlers. onAppStart, onMousePress, and redrawAll are all called for you by cmu_graphics.
Do not name your own values width or height. app.width and app.height are reserved for the canvas size.
redrawAll runs again after every event handler. Any time your data could have changed, the screen is redrawn for you. You never have to trigger a redraw by hand.

3.2.3 Model-View-Controller

a name for the structure we have been using, and the rules that keep it clean

Why Bother

Three reasons we use MVC

Clean design
Event-handling code is kept separate from drawing code. This separation of concerns means fewer bugs and clearer thinking.
Scalability
As a project grows, the MVC structure keeps the complexity manageable instead of letting it overwhelm you.
Real-world fit
Real web and mobile frameworks are built on the same idea. Learning it here prepares you for them.

This structure is what will let us build much larger apps, without drowning in our own code.

Definitions

Model, View, Controller

Model View Controller
Model   all the data the app needs, stored on the app object. In our animation the model is app.rectLeft and app.rectTop.
View   the code that draws the app from the model, and nothing else. Our view is redrawAll plus any helpers it calls.
Controller   the event handlers that respond to input and update the model. Ours are onAppStart and onMousePress. These are also called event handlers.
The Same Program, Labeled

Every function has one role

Model · the data View · draws Controller · responds

The controllers write to the model. The view reads the model. The model itself is just values sitting on app. Data flows one direction around that loop.

main.py
from cmu_graphics import *

def onAppStart(app):
    app.rectLeft = 100
    app.rectTop = 200

def onMousePress(app, mouseX, mouseY):
    app.rectLeft = mouseX
    app.rectTop = mouseY

def redrawAll(app):
    drawRect(app.rectLeft, app.rectTop,
             50, 50, fill='cyan')
The Rules

Three rules you must follow

1Never call the view or a controller yourself. They are always called for you. If you need to restart the app, write a helper like resetApp and call that from both onAppStart and wherever else you need it.
2Controllers only update the model. onMousePress must not call redrawAll or any drawing function. The redraw happens automatically when the handler finishes.
3The view never updates the model. redrawAll must not change app.rectLeft or app.rectTop. It only reads them.
When You Break Rule 2 or 3

MVC Violations

Breaking rule 2 or rule 3 is an MVC Violation. Your code stops and shows a runtime error. Read the console: it names the error and the line number, which is exactly what you need to fix it.

violation · rule 2
def onMousePress(app, mouseX, mouseY):
    app.rectLeft = mouseX
    app.rectTop = mouseY
    redrawAll(app)  # controller drew
violation · rule 3
def redrawAll(app):
    drawRect(app.rectLeft, app.rectTop,
             50, 50, fill='cyan')
    app.rectLeft = 50  # view changed the model
Checkpoint · MVC Violations

Two crashes, two reasons

Each snippet breaks an MVC rule. One crashes only after a mouse press; the other the instant the app starts. Work out why for each.

Recap

Graphics, events, and MVC

  • Every graphics program has the same skeleton: from cmu_graphics import *, a redrawAll, and main calling runApp.
  • Shapes: drawRect(left, top, width, height, fill=...) takes a corner; drawLabel(value, centerX, centerY) takes a center. On the canvas, y grows downward.
  • Tools: the Inspector reads coordinates off a drawing; the Autograder checks graphics and animations by simulating events.
  • Events: onAppStart runs once; onMousePress runs on every click with mouseX and mouseY. Store your state on app.
  • MVC: the model is data on app, the view (redrawAll) draws it, the controllers (event handlers) update it. Controllers do not draw; the view does not change data.
