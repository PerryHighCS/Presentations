What Can You Discover?

There is data about almost everything

Getting the data into your program

Right now, main.py is empty and all your data lives in a .csv file. Now we need a way to get the data from the csv file into our program, without having to type it all in by hand.

Python can open a file and read it line by line. Let's build that together before you try it on your own dataset.

Step 5, continued

A safer way: with open() as file

Closing a file matters. Normally only one program can have a file open at a time, so if your program never closes it, nothing else, not even your own program the next time it runs, can open that file again until the program ends.

Rather than opening a file and closing it manually, with open(...) as file: closes the file automatically once the indented block finishes, even if an error happens along the way.

The indentation also makes it clear which part of the program is using the file. It is good practice to use with open() whenever you work with files.

main.py
with open("movies.csv", "r") as file:
    # extract the header
    header = file.readline()
    print(header)

    # process the rest, one line at a time
    for line in file:
        line = line.strip()
        values = line.split(",")
        print(values)
Looping More Than Once

Looping through the data more than once

The for line in file pattern processes the file exactly once, start to finish. If you need multiple passes, say, one per question, it is better to load all of the lines into a variable first with readlines(), then loop over that data as many times as you like.

main.py
# load all data into one variable
with open("movies.csv", "r") as file:
    lines = file.readlines()

# remove the header line
header = lines[0]
lines = lines[1:]

# first pass: investigate one question
for line in lines:
    values = line.strip().split(",")
    # ...

# second pass: investigate another question
for line in lines:
    values = line.strip().split(",")
    # ...
Check Your Understanding

Where does the file get closed?

There's no file.close() anywhere in this code. So when does the file actually get closed? Use the line numbers to point to the exact spot.

Line 3, right after lines = file.readlines(). That's the last line still indented under with. Everything below it, including both loops, runs after the file is already closed, which is fine, since lines already holds every row in memory.

CSV, Explained

A CSV file is still just text

Each line represents one record, and commas separate the different pieces of information. Once you .strip() the newline and .split(",") the line, you have string values. Now you can use the string tools you already know: indexing, slicing, comparison, and conversion with int() or float().

The challenge is to process the data yourself, using strings, loops, conditionals, and variables.

Step 7

Design before you code

For each question, think about what your program needs to do as it examines each row. Ask yourself:

  • What information do I need from each row, and which column contains it?
  • Is that information a string, or does it need to be converted to a number?
  • What variables do I need before the loop begins?
  • What should happen each time through the loop?
  • What information do I need to remember after the loop finishes?
Break larger problems into smaller ones before writing the entire solution: this is the same top-down design habit we've seen before.
Checklist

Your program must…

  • read data from a .csv file
  • process the file using one or more loops
  • use string operations to process and examine data
  • use meaningful variables to track information
  • use conditionals where appropriate
  • answer at least three meaningful questions
  • include one question that combines or summarizes multiple records
  • clearly label its results
  • produce output a person can understand

Recap

Your data, your questions

  • Pick a dataset you care about, then look before you code: notice what's there, wonder what it can answer.
  • A CSV is just text. strip() and split(",") turn each line into values you already know how to work with.
  • Design each question before writing it: what column, what type, what variables before the loop, what to remember after.
  • Answer at least three meaningful questions, including one that combines information across records.
  • Finish with a report, not raw output: label every result so a person can read it without seeing your code.
